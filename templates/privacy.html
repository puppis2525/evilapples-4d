1. Introduction

Evil Apples 4D ("the service") is the website, the Discord bot, and the separate Telegram bot that share one PostgreSQL database. This page describes what that code stores and sends. It does not name an operator, because the codebase does not.

2. Information We Collect

Discord account data

Website login uses Discord OAuth with the identify scope only. The code requests your user id, username, global display name, and avatar, then stores them in an HttpOnly session cookie named evil_session for 30 days. The cookie is signed with the server's SESSION_SECRET. Login does not request email, guilds, or messages. The bot also stores Discord user ids and the display names players use in a game. It does not read your friend list. It does not store a general message history. It does store command inputs, button choices, wildcard answers, and an optional direct-message card number for a round that is already in progress.

Game data

PostgreSQL stores active game sessions as JSON, finished rounds (prompt, winning card, winner id, winner name, and a public slug), leaderboard rows (id, name, wins, games played), tournaments, teams, and custom decks. Round pages and the leaderboard are public. Custom deck text and wildcard answers are stored and can be sent to the AI provider described below. Telegram rows use the same tables, distinguished by a platform column, and Telegram user ids are stored with a tg_ prefix where that code path writes them.

Payment information

Card numbers are entered on Stripe Checkout, not on this service. The code stores Stripe customer ids, subscription ids, Checkout session ids, payment intent ids, connected-account ids, amounts, and status. Checkout metadata includes Discord or Telegram ids, names, guild or chat ids, plan name, tournament id, and sponsor name. Webhook deliveries are verified with STRIPE_WEBHOOK_SECRET and the event id is recorded so a retry does not apply the same payment twice. Keys can be supplied as environment variables. A Replit connector is used only when those variables are empty and the connector is configured.

Server and guild data

The service stores Discord guild ids, channel ids, premium plan, who activated it, tournament links, and a periodic count of guilds the bot is in. It does not request the guild members or presence intents in the default configuration.

Telegram

The Telegram bot stores chat ids, group titles, user ids, display names, game stats, and one-time group-unlock payments. It is a separate process and keeps working when the Discord bot changes. Its site is served from the Telegram templates and, on the shared host, may be reached through the evilapples4tg.com proxy.

Automatically collected data

Rate limiting keeps recent request times in process memory, keyed by the first X-Forwarded-For address when that header is present, otherwise by the connection address. A rate_limit_entries table is created by migrations, but the limiter in server.py does not write to it. The app logs rate-limit warnings and Discord login id plus display name. Host or proxy logs may also record IP addresses; that depends on where the operator runs the process. Ad clicks increment a counter and redirect to the advertiser's URL. They are not stored with a user id. If ADSENSE_PUBLISHER_ID is set, public pages can load Google AdSense.

3. How We Use Your Information

  • To operate and improve the Evil Apples 4D game experience
  • To track scores, leaderboards, and tournament standings
  • To process payments and manage premium subscriptions
  • To manage custom card decks and store purchases
  • To display ads to non-premium users
  • To detect abuse, cheating, and unauthorized use
  • To communicate important service updates

4. Third-Party Services

Discord

We use Discord's API and OAuth2 for authentication and bot functionality. Your use of Discord is governed by Discord's Privacy Policy.

Stripe

Payment processing is handled by Stripe. When you make a payment, your financial information is transmitted directly to Stripe and is subject to Stripe's Privacy Policy.

Venice.ai

Card generation, judging, and the Dr. Evil roast call Venice.ai's chat API with the prompt text and the answer text. Those requests send the card lines. They do not include a Discord user id, email, or the session cookie. Venice receives whatever is inside the card text itself.

Google

Optional. AdSense loads only when a publisher id is configured. The service also loads Google fonts on these pages.

5. Data Storage and Security

The database is whatever PostgreSQL instance DATABASE_URL points at. Replit is one possible host, not a requirement. The app expects HTTPS in production, signs session cookies, and rejects Stripe webhooks when the webhook secret is missing or the signature does not match. No storage method is perfectly secure.

6. Data Retention

We retain your game data and account information for as long as your account is active or as needed to provide our services. If you wish to have your data deleted, please contact us (see below). Payment records may be retained as required by law or for legitimate business purposes (e.g., tax records, dispute resolution).
